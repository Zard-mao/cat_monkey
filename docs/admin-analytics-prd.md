# Monkey 审核后台数据看板产品文档

版本：v0.2
日期：2026-05-27
状态：本地开发版已实现，待确认后发布

## 1. 背景与目标

当前 Monkey 朋友圈已经支持用户投稿、审核、公开展示，以及喜欢、点赞、点踩互动。审核后台目前主要解决“内容是否通过”的问题，还缺少投稿和互动数据的查看能力。

本模块希望在审核人员登录后，增加一个数据看板，让审核人员可以快速了解：

- 每天有多少投稿。
- 每天投稿通过、拒绝、待审核的情况。
- 每个投稿的互动表现。
- 哪些投稿更受欢迎，哪些投稿收到较多点踩。
- 可按日期、投稿人和互动类型筛选查看。

核心目标：

- 帮助审核人员掌握 Monkey 朋友圈的内容活跃度。
- 支持按天查看投稿数据，不需要导出表格也能完成日常判断。
- 支持按投稿人查看历史投稿和互动表现。
- 支持按喜欢、点赞、点踩数量排序，快速发现高互动内容。
- 不改变普通访客体验；该功能只在审核后台登录后可见。

## 2. 用户角色

审核人员：

- 登录审核后台。
- 查看投稿统计和单条投稿互动数据。
- 按日期、投稿人、状态、互动类型筛选内容。
- 根据互动数据辅助判断内容是否需要重新审核。

站点管理员：

- 拥有审核人员能力。
- 后续可扩展导出数据、查看趋势图、管理异常互动等能力。

普通访客：

- 无法访问数据看板。
- 不需要登录。
- 不感知后台统计功能。

## 3. 功能入口

页面位置：

- 在现有 `/admin.html` 审核后台登录后展示。
- 不新增普通访客入口。

后台登录后的主结构：

- 顶部：登录状态、退出按钮。
- 一级 tab：
  - `投稿审核`
  - `数据看板`

第一版不新增独立页面；在现有审核后台登录成功后，通过顶部 tab 切换查看两个模块：

- `投稿审核`：保留现有待审核、已通过、已拒绝分栏和审核操作。
- `数据看板`：展示每日投稿、投稿人筛选和互动数据排序。

tab 交互要求：

- 两个 tab 位于审核后台内容区顶部，登录状态栏下方。
- 切换 tab 不需要重新登录。
- 切换到 `投稿审核` 时保留原有审核分栏状态，例如仍停留在 `待审核` 或 `已通过`。
- 切换到 `数据看板` 时保留看板筛选条件，例如日期、投稿人、状态和排序。
- 刷新页面后第一版可回到默认 tab；后续可用本地状态记住上次打开的 tab。

默认进入：

- 如果存在待审核投稿，默认进入 `投稿审核`。
- 如果没有待审核投稿，可默认进入 `数据看板` 或保持 `投稿审核` 空状态。

## 4. 数据看板页面结构

### 4.1 顶部概览

顶部展示当前筛选范围内的核心指标。

指标卡片：

- 投稿总数
- 待审核数
- 已通过数
- 已拒绝数
- 喜欢总数
- 点赞总数
- 点踩总数
- 互动总数

计算范围：

- 默认按“今天”统计。
- 当用户修改日期范围后，所有指标随筛选条件变化。

默认日期：

- 初次进入默认展示今天。
- 可快速切换：
  - 今天
  - 昨天
  - 最近 7 天
  - 最近 30 天
  - 自定义日期范围

### 4.2 每日投稿情况

展示每天投稿数量和状态分布。

字段：

- 日期
- 投稿总数
- 待审核数
- 已通过数
- 已拒绝数
- 当日喜欢总数
- 当日点赞总数
- 当日点踩总数

展示方式：

- 第一版使用表格。
- 后续可增加简单柱状图。

点击行为：

- 点击某一天，自动将下方投稿列表筛选到该日期。
- 当前选中的日期需要高亮。

### 4.3 投稿列表与互动数据

展示符合筛选条件的投稿。

每条投稿展示：

- 投稿图片缩略图
- 投稿人昵称
- 投稿描述
- 标签
- 投稿时间
- 审核状态
- 审核时间
- 喜欢数
- 点赞数
- 点踩数
- 互动总数
- 当前后台可执行操作：
  - 查看详情
  - 通过
  - 改为不通过
  - 改为通过

图片展示要求：

- 与朋友圈公开页一致，完整展示图片。
- 比例不一致时允许上下或左右留深色边。
- 不裁切 Monkey 主体。

### 4.4 投稿详情

点击“查看详情”后展示单条投稿详情。

详情字段：

- 大图预览
- 投稿人昵称
- 投稿描述
- 标签
- 投稿时间
- 审核状态
- 审核时间
- 审核人员
- 拒绝原因
- 喜欢数
- 点赞数
- 点踩数
- 互动总数

第一版不展示每个访客的具体身份明细，只展示汇总计数。

后续可扩展：

- 最近互动时间。
- 互动趋势。
- 异常互动提示。

## 5. 筛选与排序

### 5.1 日期筛选

支持：

- 今天
- 昨天
- 最近 7 天
- 最近 30 天
- 自定义开始日期和结束日期

日期口径：

- 投稿情况按 `createdAt` 投稿时间统计。
- 审核状态按投稿当前状态统计。
- 互动计数为投稿当前累计互动数。

注意：

- 如果一个投稿今天提交，明天通过，按“投稿日期”仍归属于今天。
- 如果后续需要按“审核通过日期”统计，可增加切换项。

### 5.2 投稿人筛选

支持按投稿人昵称筛选。

交互方式：

- 输入框搜索投稿人昵称。
- 支持模糊搜索。
- 可清空筛选条件。

第一版不需要联系方式，也不展示联系方式。

原因：

- 当前投稿不收集联系方式。
- 投稿人仅以昵称作为筛选依据。

### 5.3 状态筛选

支持：

- 全部
- 待审核
- 已通过
- 已拒绝

默认：

- 数据看板默认展示全部状态。
- 投稿审核页仍默认展示待审核。

### 5.4 标签筛选

支持使用现有标签：

- 办公室
- 读书
- 巡逻
- 可爱瞬间
- AI生成
- 其他

第一版可选做。

建议优先级：

- 日期筛选：必须
- 投稿人筛选：必须
- 状态筛选：必须
- 互动排序：必须
- 标签筛选：可延后

### 5.5 互动类型排序

支持排序字段：

- 投稿时间
- 喜欢数
- 点赞数
- 点踩数
- 互动总数

排序方向：

- 从高到低
- 从低到高

默认排序：

- 投稿时间从新到旧。

常用排序入口：

- `按喜欢最多`
- `按点赞最多`
- `按点踩最多`
- `按互动最多`
- `按最新投稿`

## 6. 数据口径

### 6.1 投稿统计

投稿总数：

- 符合筛选条件的投稿数量。

待审核数：

- `status = pending`

已通过数：

- `status = approved`

已拒绝数：

- `status = rejected`

### 6.2 互动统计

喜欢数：

- 投稿 `reactionCounts.favorite`

点赞数：

- 投稿 `reactionCounts.like`

点踩数：

- 投稿 `reactionCounts.dislike`

互动总数：

- `favorite + like + dislike`

### 6.3 投稿人统计

投稿人：

- 使用投稿时填写的 `nickname`。

注意：

- 当前系统不要求登录投稿，也不收集联系方式。
- 同名投稿人可能不是同一个真实用户。
- 第一版仅按昵称筛选，不做真实用户合并。

## 7. 后端接口建议

### 7.1 获取后台数据看板

新增接口：

- `GET /.netlify/functions/admin-analytics`

权限：

- 必须带审核后台 token。
- 未登录或 token 失效返回 401。

查询参数：

- `dateFrom`：开始日期，格式 `YYYY-MM-DD`
- `dateTo`：结束日期，格式 `YYYY-MM-DD`
- `nickname`：投稿人昵称，支持模糊匹配
- `status`：`all`、`pending`、`approved`、`rejected`
- `sortBy`：`createdAt`、`favorite`、`like`、`dislike`、`totalInteractions`
- `sortOrder`：`desc`、`asc`

返回结构建议：

    "approved": 9,

### 7.2 复用现有审核接口

状态变更继续复用：

- `POST /.netlify/functions/review-moment`

原因：

- 数据看板里的通过、拒绝、改为通过、改为不通过，本质仍是审核状态变更。
- 避免新增重复接口。

## 8. 页面交互

### 8.1 桌面端

推荐布局：

- 顶部：核心指标卡片横向排列。
- 中部：筛选区。
- 下方左侧：每日投稿表格。
- 下方右侧或下方主区域：投稿列表。

筛选区控件：

- 日期快捷按钮
- 开始日期
- 结束日期
- 投稿人搜索框
- 状态下拉或分段按钮
- 排序下拉

### 8.2 手机 H5

推荐布局：

- 指标卡片横向滑动或两列网格。
- 筛选区折叠为“筛选”按钮。
- 每日投稿情况使用紧凑列表。
- 投稿列表单列展示。

手机端注意：

- 不做复杂大表格横向滚动。
- 每条投稿优先展示图片、昵称、状态和互动数。
- 详情信息放入展开面板或详情页。

## 9. 权限与安全

- 数据看板只对审核后台登录用户可见。
- 所有数据看板接口必须校验审核 token。
- 不在前端写死审核账号密码。
- 不展示投稿用户联系方式，因为系统不收集联系方式。
- 不暴露访客 `visitorId` 明细给后台第一版页面。
- 如果后续开放导出，需要单独增加权限确认。

## 10. 空状态与异常状态

无数据：

- 文案：`当前筛选条件下还没有投稿。`

接口失败：

- 文案：`数据暂时加载失败，请稍后重试。`

登录失效：

- 自动回到审核后台登录页。
- 文案：`登录已失效，请重新登录。`

筛选无结果：

- 保留筛选条件。
- 提供 `清空筛选` 操作。

## 11. 第一版优先级

必须做：

- 登录后可进入数据看板。
- 今日 / 昨日 / 最近 7 天 / 自定义日期筛选。
- 投稿人昵称筛选。
- 状态筛选。
- 投稿列表展示喜欢、点赞、点踩、互动总数。
- 按喜欢、点赞、点踩、互动总数排序。
- 每日投稿统计。

可以延后：

- 标签筛选。
- 图表可视化。
- 数据导出。
- 访客互动明细。
- 异常互动提醒。

## 12. 验收标准

- 审核人员登录后可以看到 `投稿审核` 和 `数据看板` 两个入口。
- 数据看板默认展示今天的投稿情况。
- 可以切换日期范围查看不同日期投稿数据。
- 可以输入投稿人昵称筛选投稿。
- 可以按状态筛选投稿。
- 可以按喜欢数、点赞数、点踩数、互动总数排序。
- 每条投稿能看到三类互动计数。
- 每日投稿统计与投稿列表筛选范围一致。
- 未登录用户不能访问数据看板接口。
- 手机端可以正常浏览和筛选，不出现内容严重溢出。
