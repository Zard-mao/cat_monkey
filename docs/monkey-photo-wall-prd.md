# Monkey 照片墙朋友圈功能产品文档

版本：v0.2  
日期：2026-05-25  
状态：产品方案草稿，未进入开发

## 1. 背景与目标

当前 Monkey 个人主页以“赛博猫档案”为主，展示 Monkey 的真实日常照和 AI 奇幻职业图。下一阶段希望增加一个独立的“照片墙朋友圈”页面，让其他用户也可以上传 Monkey 的照片和描述，形成类似微信朋友圈的信息流。

核心目标：

- 增加一个 Monkey 日常照片墙页面，展示经审核通过的用户投稿。
- 支持访客上传 Monkey 照片、描述、昵称等投稿内容。
- 所有投稿默认进入待审核状态，不能直接公开展示。
- 增加一个独立审核页面，审核人员登录后可以在后台查看、通过、拒绝投稿。
- 支持访客对已发布内容进行喜欢、点赞、点踩，并展示互动计数。
- 页面整体风格延续 Monkey 主页，不做通用社交平台感。

## 2. 用户角色

访客用户：

- 浏览 Monkey 照片墙。
- 上传 Monkey 照片。
- 填写照片描述和自己的昵称。
- 看到投稿提交成功提示。
- 对已发布内容进行喜欢、点赞、点踩。

审核人员：

- 使用审核账号和密码进入审核页面。
- 查看待审核投稿。
- 预览图片、描述、投稿时间和投稿人昵称。
- 执行通过或拒绝。
- 查看已通过、已拒绝记录。

站点管理员：

- 拥有审核人员的所有能力。
- 后续可扩展删除已发布内容、恢复误拒内容、管理敏感词等能力。

## 3. 功能范围

### 3.1 照片墙朋友圈页面

页面路径建议：

- `/moments.html`
- 中文导航名称：`Monkey 朋友圈`

页面内容：

- 顶部保留 Monkey 档案风格导航，可返回首页。
- 首屏标题：`Monkey 朋友圈`
- 副标题：`大家捕捉到的 Monkey 日常瞬间`
- 信息流卡片展示已审核通过的投稿。

卡片字段：

- Monkey 照片
- 用户昵称
- 照片描述
- 发布时间
- 审核通过时间
- 可选标签，例如 `办公室`、`读书`、`犯困`、`巡逻`、`可爱瞬间`、`AI生成`、`其他`
- 互动计数：`喜欢`、`点赞`、`点踩`
- 当前访客已选择的互动状态

信息流排序：

- 默认按审核通过时间倒序。
- 最新通过的内容排在最前。

空状态：

- 如果暂无投稿，显示 `还没有新的 Monkey 瞬间`。
- 提供上传入口。

### 3.2 投稿上传

上传入口：

- 照片墙页面顶部或悬浮按钮。
- 文案建议：`上传 Monkey 照片`

投稿表单字段：

- 照片：必填，支持 jpg、jpeg、png、webp。
- 描述：必填，最多 120 字。
- 昵称：必填，最多 20 字。
- 标签：选填，可从预设标签中选择。第一版预设包含 `办公室`、`读书`、`巡逻`、`可爱瞬间`、`AI生成`、`其他`。

上传限制：

- 单次提交 1 张照片。
- 每个用户每天最多发布 3 次。
- 图片大小建议限制为 8MB 以内。
- 前端显示文件大小和格式错误提示。
- 达到每日 3 次上限后，投稿按钮置灰，提示 `今天已经投稿 3 次，明天再来捕捉 Monkey。`
- 投稿提交后进入 `待审核`，不立即出现在照片墙。

提交成功状态：

- 弹出或页面内提示：`投稿成功，审核通过后会出现在 Monkey 朋友圈。`
- 不承诺具体审核时效。

### 3.3 审核后台页面

页面路径建议：

- `/admin.html`
- 或后续接入身份系统后使用 `/admin/moments`

进入方式：

- 审核后台必须登录后访问。
- 朋友圈公开页和投稿页不需要登录。
- 第一版由部署环境配置 1 组审核人员账号密码：
  - 审核账号：通过 `REVIEWER_USERNAME` 环境变量配置。
  - 审核密码：通过 `REVIEWER_PASSWORD` 环境变量配置。
- 账号密码必须保存在服务端环境变量或后端配置中，不能写入前端代码。
- 真实密码不得写入 GitHub、前端代码或公开文档；后续可接入 Netlify Identity 或其他登录机制。

登录页面字段：

- 审核账号
- 密码
- 登录按钮
- 登录失败提示

审核列表分栏：

- 待审核
- 已通过
- 已拒绝

待审核卡片字段：

- 投稿图片
- 昵称
- 描述
- 标签
- 投稿时间
- 审核操作按钮

审核操作：

- `通过`：内容进入公开照片墙。
- `拒绝`：内容不公开展示。
- `已通过`内容可在后台改为不通过，改为不通过后从公开朋友圈隐藏。
- `已拒绝`内容可在后台重新改为通过，改为通过后进入公开朋友圈。
- `查看大图`：打开预览。

拒绝原因：

- 第一版可选填。
- 后续可扩展常用原因：
  - 图片不是 Monkey
  - 图片不清晰
  - 描述不合适
  - 重复投稿
  - 其他

### 3.4 状态流转

投稿状态：

- `pending`：待审核
- `approved`：已通过
- `rejected`：已拒绝

状态规则：

- 新投稿默认是 `pending`。
- 只有 `approved` 内容可在照片墙公开展示。
- `rejected` 内容不展示给普通访客。
- 审核页面登录后可查看全部状态。
- 未登录或登录失效时，访问审核页面应跳转到审核登录页。

### 3.5 内容互动

互动类型：

- `喜欢`
- `点赞`
- `点踩`

互动规则：

- 每条已发布内容展示三类互动按钮和对应计数。
- 访客点击后按钮进入选中态，再次点击取消选中态。
- 三类互动互不互斥，同一访客可以同时喜欢和点赞，也可以单独点踩。
- 服务端需要记录每个访客对每条内容的互动状态，避免刷新后丢失。
- 第一版可用浏览器本地生成的 `visitorId` 匿名识别访客，存储在 `localStorage`；后续有正式用户体系后切换为真实用户 ID。
- 互动计数以服务端返回为准，前端点击后可先做轻量即时反馈，再用服务端结果校准。

## 4. 页面体验要求

### 4.1 照片墙页面体验

整体感觉：

- 像 Monkey 的私人朋友圈，不像普通图片上传站。
- 卡片有轻微档案感，但比首页更生活、更轻松。
- 重点突出照片和一句描述。

移动端：

- 信息流单列展示。
- 上传按钮固定在底部或页面顶部显眼位置。
- 图片保持合理比例，避免裁掉 Monkey 的脸。

桌面端：

- 可使用双列或瀑布流布局。
- 上传入口保持可见。

### 4.2 审核后台体验

审核效率优先：

- 待审核内容应一屏能看到多条。
- 通过 / 拒绝按钮明显区分。
- 点击通过后立即从待审核列表移出。
- 操作完成后显示轻量提示。

防误操作：

- 拒绝建议二次确认或提供撤销。
- 通过可不二次确认，但需要有操作反馈。

## 5. 数据模型建议

投稿记录 `momentPost`：

```json
{
  "id": "post_001",
  "imageUrl": "/uploads/post_001.jpg",
  "thumbnailUrl": "/uploads/post_001_thumb.jpg",
  "description": "Monkey 今天认真研究一本书。",
  "nickname": "投稿人昵称",
  "tags": ["读书", "日常"],
  "status": "pending",
  "reactionCounts": {
    "favorite": 0,
    "like": 0,
    "dislike": 0
  },
  "createdAt": "2026-05-25T10:00:00+08:00",
  "reviewedAt": null,
  "reviewedBy": null,
  "rejectReason": null
}
```

访客互动记录 `momentReaction`：

```json
{
  "postId": "post_001",
  "visitorId": "visitor_abc",
  "favorite": true,
  "like": true,
  "dislike": false,
  "updatedAt": "2026-05-25T10:30:00+08:00"
}
```

公开照片墙只读取：

- `status = approved`

审核后台读取：

- `pending`
- `approved`
- `rejected`

## 6. 技术实现建议

当前站点是静态页面，已部署在 Netlify。推荐使用 Netlify 能力实现第一版：

- 前端页面：静态 HTML / CSS / JS。
- 图片存储：Netlify Blobs。
- 投稿 API：Netlify Functions。
- 审核 API：Netlify Functions。
- 表单防刷：简单频率限制 + 文件大小限制。
- 后台登录：第一版可用环境变量配置审核密码，正式版再接入身份系统。

建议接口：

- `POST /.netlify/functions/submit-moment`
  - 接收图片、描述、昵称、标签。
  - 校验同一用户每日投稿次数是否超过 3 次。
  - 保存图片和投稿数据。
  - 返回投稿成功。

- `GET /.netlify/functions/list-moments?status=approved`
  - 普通照片墙读取公开内容。
  - 返回互动计数和当前访客互动状态。

- `POST /.netlify/functions/login-reviewer`
  - 参数：`username`、`password`
  - 校验审核账号密码。
  - 成功后返回审核后台访问凭证。

- `GET /.netlify/functions/admin-list-moments?status=pending`
  - 审核后台读取指定状态内容。
  - 需要审核后台访问凭证。

- `POST /.netlify/functions/review-moment`
  - 参数：`id`、`action`、`rejectReason`
  - `action` 支持 `approve`、`reject`
  - 需要审核后台访问凭证。
  - 可用于待审核、已通过、已拒绝内容的状态变更。

- `POST /.netlify/functions/react-moment`
  - 参数：`postId`、`reactionType`、`selected`、`visitorId`
  - `reactionType` 支持 `favorite`、`like`、`dislike`
  - `selected` 为布尔值，表示本次操作后的目标状态。
  - 保存当前访客的互动状态。
  - 返回最新互动计数和当前访客互动状态。

- `GET /uploads/:id`
  - 读取用户投稿图片原始文件。
  - 主要作为 Netlify Image CDN 的源图路径使用，不建议前端直接展示原图。

## 6.1 互动和图片性能策略

互动反馈：

- 喜欢、点赞、点踩采用前端乐观更新。
- 用户点击后，按钮选中态和计数立即变化。
- 同一个内容的同一个互动按钮在同步期间进入短暂锁定状态，避免弱网下重复点击。
- 服务端接口接收明确的 `selected` 状态，而不是只做 toggle 反转。
- 服务端同步成功后以前端返回数据校准；失败时前端回滚到点击前状态，并提示用户稍后再试。

图片加载：

- 朋友圈公开页和审核后台不直接展示用户上传原图。
- 用户上传图通过 `/uploads/:id` 作为源图，再交给 Netlify Image CDN 按不同宽度输出 WebP 展示图。
- 前端为照片使用 360、640、960 三档响应式图片，手机端优先加载小尺寸。
- 朋友圈公开页和审核后台使用完整展示模式，图片不裁切；比例不匹配时允许上下或左右出现深色留边。
- 非首屏图片使用 `loading="lazy"` 和 `decoding="async"`，减少首次打开压力。
- 首页首屏主图使用 Netlify Image CDN 输出 WebP 压缩图，保留视觉质量同时降低移动端加载成本。

## 7. 内容审核规则

通过条件：

- 照片主体是 Monkey 或明显与 Monkey 有关。
- 图片不包含敏感、隐私、攻击性内容。
- 描述友好、不包含辱骂、广告或引流信息。
- 图片质量基本可见。

拒绝条件：

- 明显不是 Monkey。
- 内容重复或过于模糊。
- 描述含敏感词、广告或不适合公开展示的信息。
- 上传者疑似恶意刷屏。

隐私注意：

- 若照片包含明显人脸、工位敏感信息、聊天记录、手机号等，应拒绝或要求裁剪后再发布。

## 8. 版本规划

### v1：最小可用版本

- 新增 Monkey 朋友圈页面。
- 支持用户上传 1 张照片和描述。
- 限制每个用户每天最多投稿 3 次。
- 投稿进入待审核。
- 审核后台需要登录，并支持通过 / 拒绝。
- 公开页面只展示已通过内容。
- 支持喜欢、点赞、点踩计数和选中态。

### v1.1：体验优化

- 图片压缩和缩略图。
- 投稿成功后显示投稿编号。
- 审核后台支持大图预览。
- 支持拒绝原因。

### v1.2：社区感增强

- 支持按标签筛选。
- 支持精选置顶。
- 支持“今日 Monkey 瞬间”。

## 9. 验收标准

- 普通访客可以进入 Monkey 朋友圈页面查看已审核照片。
- 普通访客提交照片后，内容不会立即公开。
- 普通访客每天最多投稿 3 次，超过后无法继续提交。
- 普通访客可以对已发布内容喜欢、点赞、点踩，并看到计数变化和选中态。
- 刷新页面后，普通访客已产生的互动状态仍能恢复。
- 朋友圈公开页和投稿页不要求登录。
- 审核后台登录页使用部署环境配置的审核账号和密码进入。
- 审核人员可以在后台看到待审核投稿。
- 审核通过后，投稿出现在公开照片墙。
- 审核拒绝后，投稿不会出现在公开照片墙。
- 移动端上传、浏览、审核页面都能正常使用。
- 不登录或未授权用户不能进入审核操作。

## 10. 暂不包含

- 评论功能。
- 多图一次上传。
- 用户个人主页。
- 自动 AI 审核。
- 复杂权限系统。
